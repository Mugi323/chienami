# Chienami Search UI の動作確認（Issue #36）

`app/search-ui/` に追加した静的ファイル（素のHTML/CSS/JS、ビルド不要）を、Caddyが
`https://portal.lab.local/search/` として配信する（Issue #90で `search.lab.local` から移行）。
`/search/api/*` は同一オリジンで `chienami-api`（Issue #34）へリバースプロキシされるため、
ブラウザ側のCORS設定は不要。

> 会話履歴はブラウザのlocalStorage（オリジン単位）に保存されるため、`search.lab.local` 時代の
> 履歴は移行後のURLからは見えない（移行は行わない）。

## 前提

- Issue #26（Reverse ProxyのHTTPS化）・#34（chienami-api）が導入済みであること。
- 各端末で `portal.lab.local` を開けること（[reverse-proxy-setup.md](reverse-proxy-setup.md)）。

## 1. サーバ側の起動確認

```bash
docker compose up -d --force-recreate caddy
docker compose ps caddy
```

## 2. 画面構成（Issue #68でチャット型に刷新）

ヘッダーのないサイドバー型レイアウト。色はすべて `style.css` 冒頭のCSS変数（`--color-*`）で管理している。

- **サイドバー**: ロゴ / 「新しいチャット」 / 会話履歴 / ナビ（AI回答・検索・Outline・ポータル）
- **メインエリア**: メッセージ（ユーザーはゴールドのバブル、AIはアバター付きのバブルなし表示）と、画面下部のフローティング入力欄
- **入力欄**: Enterで送信、Shift+Enterで改行（日本語変換中のEnterでは送信しない）。高さは内容に合わせて160pxまで伸びる
- **モバイル（768px以下）**: サイドバーは隠れ、左上のメニューボタンで開閉する（背景のオーバーレイを押すと閉じる）

### 会話履歴（localStorage）

- AI回答の会話（質問・回答・出典）は、**ブラウザのlocalStorage**（キー `chienami.conversations.v1`）に保存する。サーバには送らず、保存もしない
- 同じ端末・同じブラウザでのみ表示される。ブラウザのサイト データを消すと消える
- 直近50件まで保存し、古いものから消える。タイトルは最初の質問の先頭30文字
- 履歴にマウスを乗せると出る×で削除できる（確認なし）
- AIは過去のやり取りを文脈として使わない（各質問は独立して `/chat` に送られる）
- 回答に失敗した質問は履歴に残さず、入力欄に戻す
- 検索モードの結果は履歴に保存しない
- 保存処理は `createConversationStore()`（`app.js`）にまとめてあり、将来サーバ保存へ差し替えられる

## 3. ブラウザでの確認

1. `https://portal.lab.local/search/` を開く（証明書エラーが出る場合はルートCAの信頼登録を確認）。
2. サイドバーの「検索」でキーワードを入力して送信し、結果カードのタイトル・「Outlineで開く →」リンクの両方から該当のOutlineページ（`https://knowledge.lab.local/...`）を新しいタブで開けることを確認する。
3. 該当する文書が無いキーワードで検索し、「一致する文書が見つかりませんでした。」が表示されることを確認する。
4. `chienami-api` を一時的に停止し（`docker compose stop api`）、検索してエラー表示（「検索APIに接続できませんでした」等）になることを確認した後、再起動する（`docker compose start api`）。

### AI回答（Phase 4, Issue #63）

サイドバーの「AI回答」（既定）では、入力した質問を `POST /api/chat`（[rag-setup.md](rag-setup.md)）へ送り、研究室の知識ベースだけを根拠にした回答を表示する。

- 出典は、回答の下に1件1行（`S1` 等の番号・タイトル・関連度）で簡易表示する。本文は表示せず、タイトルから該当のOutlineページを新しいタブで開いて読む（Issue #78）
- 回答本文の `S1` などのチップを押すと、同じ番号の出典行へスクロールし、ハイライトする
- 出典は、回答で引用されたものは通常表示、引用されなかったものは薄く表示する（「未引用」）
- 根拠が見つからず回答を控えた場合は、その旨と「通常の検索で探す →」を表示する。押すと同じ文言で検索モードの検索を行う
- AIサービス（LLM/Reranker）が停止している場合（503）は、「検索」を使うよう案内する
- 回答生成中は送信ボタンを無効にする（二重送信の防止）
- 回答本文は、HTMLとして解釈せずテキストとして表示する
- 回答本文のMarkdownのうち、LLMがよく使う記法だけを整形して表示する（Issue #79）
  - コードブロック（```` ``` ```` / `~~~`）: 等幅・濃い背景で表示し、言語名と「コピー」ボタンを付ける。中の記号や `[S1]` はそのまま表示する
  - インラインコード（`` `ls` ``）、太字（`**…**`）、見出し（`#`〜`######`）、箇条書き・番号付きリスト、区切り線（`---`）
  - 表・引用・リンク記法・入れ子のリスト（平坦に表示）には対応しない。変換は `parseMarkdown()` / `parseInline()`（`app.js`）で行い、DOMノードとして組み立てるためHTMLは解釈しない
  - コードの色分け（シンタックスハイライト）は未対応（Issue #85）
  - LLMには、コマンドやコードを言語名付きのコードブロックで書き、Source IDはブロックの外に付けるようプロンプトで指示している（`rag.py`）

## 4. 開発機での確認方法

UIの純関数（回答中の `[Sn]` の分解、Markdownの分解、会話履歴の保存処理）は、Node.jsの単体テストで確認できる。

```bash
node --test app/search-ui/tests/*.test.js
```

Node.jsが入っていない環境では、`uvx --from nodejs-wheel node --test app/search-ui/tests/*.test.js` でも実行できる。
